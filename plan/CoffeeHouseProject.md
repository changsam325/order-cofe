# 線上咖啡點餐系統｜開發企劃案

## 1. 專案概述

本專案規劃一套以手機點餐體驗為優先的咖啡品牌網站。顧客端採用**傳統多頁式 HTML**：首頁、菜單、購物車、結帳與訂單查詢各自使用獨立 HTML 檔案，透過一般 `<a href>` 連結前往；共用導覽、頁尾與資料處理由 JavaScript 模組負責，避免把不同任務擠在同一個長頁面。菜單初始商品資料集中於 JSON 檔，避免在各頁重複維護。

### 專案目標

- **顧客端**：快速瀏覽菜單、客製飲品、完成結帳並追蹤訂單。
- **店家端**：集中查看新訂單、更新製作狀態、管理商品供應情形。
- **品牌體驗**：依 `UI style/ui1.webp` 的精品咖啡視覺方向，呈現深焙色調、咖啡影像與清楚的行動呼籲。
- **裝置支援**：以行動裝置為優先，並支援平板與桌面瀏覽。

## 2. 網站資訊架構

### 顧客端頁面

| 路由建議 | 頁面 | 主要內容 |
|---|---|---|
| `index.html` | 首頁 | 品牌主視覺、招牌推薦、品牌故事入口、前往菜單與購物車 |
| `menu.html` | 菜單 | 分類瀏覽、搜尋、標籤篩選、商品客製化 |
| `cart.html` | 購物車 | 品項、客製內容、數量、小計與移除操作 |
| `checkout.html` | 結帳 | 取餐方式、聯絡資料、付款方式、訂單確認 |
| `order.html?id=:orderId` | 訂單查詢／追蹤 | 輸入訂單編號查詢，呈現訂單摘要與「已收單 → 製作中 → 請取餐 → 已完成」進度 |

### 管理端頁面

| 路由建議 | 頁面 | 主要內容 |
|---|---|---|
| `admin.html` | 訂單看板 | 新進訂單提示、訂單分欄、更新處理狀態 |
| `admin.html?view=menu` | 菜單管理 | 新增／編輯商品、上架／下架、缺貨設定 |

管理端應與顧客端分開導覽，並在正式上線前加入適當的登入與權限控管。未登入或無管理權限時，不應開放管理操作。

## 3. 核心功能

### 顧客點餐流程

1. **菜單瀏覽**：熱門推薦、義式咖啡、手沖精品、嚴選茶飲、特調氣泡、無咖啡因與手作甜點；支援搜尋及分類篩選。
2. **商品客製**：容量、冷熱／冰量、甜度、加料選擇；商品不適用的選項應隱藏或停用。
3. **購物車**：顯示品項與客製明細，支援修改數量、移除品項及計算金額。
4. **結帳**：支援現場自取、內用桌號、外送等取餐方式，以及 LINE Pay、信用卡、現場支付等付款選項；實際可用項目依門市設定。
5. **訂單追蹤**：以訂單編號顯示狀態與摘要；即時更新失敗時需提供清楚的重新整理／重試方式。

### 店家管理流程

- 訂單依狀態分欄呈現；可用按鈕更新狀態，並視操作情境支援拖曳。
- 新訂單提供畫面提示；音效需由使用者互動後啟用，且不可作為唯一通知方式。
- 菜單可設定供應中、暫停供應與缺貨，避免顧客訂購無法製作的品項。

## 4. UI／UX 設計方向

- **參考素材**：`UI style/ui1.webp`；以精品咖啡照片、深色大圖區塊與俐落的商品卡片為視覺基礎。
- **色彩**：深焙褐 `#2D211B`、咖啡棕 `#6F4E37`、奶油白 `#F5EBE6`、暖金 `#D4AF37`、柔白 `#FAFAFA`。
- **字體**：中文使用 Chiron GoRound TC、英文使用 EB Garamond；裝飾性英文可採斜體，所有介面字級均須大於 12px。
- **首頁**：品牌導覽、主視覺與主要 CTA、招牌商品、品牌故事／產地介紹、頁尾資訊。
- **點餐頁**：分類清楚、價格易辨識、客製選項適合觸控；加購與購物車狀態需有明確回饋。
- **響應式**：手機版導覽精簡、按鈕有足夠觸控尺寸、商品卡與表單依螢幕寬度調整。
- **無障礙**：語意化標籤、鍵盤可操作、圖片替代文字、足夠對比與清楚的表單錯誤訊息。

顧客端採多頁式實作：[`index.html`](../index.html)、[`menu.html`](../menu.html)、[`cart.html`](../cart.html)、[`checkout.html`](../checkout.html) 與 [`order.html`](../order.html) 各自負責一個頁面，頁面間使用一般連結；固定文案、頁面結構、導覽列、頁尾與表單欄位直接寫在 HTML。管理功能暫由 [`admin.html`](../admin.html) 獨立提供。共用樣式集中於 `assets/css/styles.css`，共用工具與互動集中於 `assets/js/app.js`，各頁互動邏輯分別放在 `assets/js/home.js`、`menu.js`、`cart.js`、`checkout.js`、`order.js` 與 `admin.js`。

商品初始資料集中於 [`data/products.json`](../data/products.json)，由共用模組載入並供首頁推薦、菜單與管理頁使用；商品圖片使用 `plan/images/` 內的本機檔案。JS 僅負責商品卡、購物車、訂單與管理清單等動態資料，以及搜尋、客製、送單和狀態更新等互動；固定頁面文案與表單結構留在 HTML。管理頁的商品編輯僅儲存於目前瀏覽器的 `localStorage`，作為 JSON 初始資料之上的本機展示覆寫，不會回寫 JSON 檔案；更新商品目錄版本時，會以新版 JSON 重新初始化舊的本機菜單快取。因瀏覽器以 `fetch()` 讀取 JSON，開發時須透過本機 HTTP 伺服器（例如 VS Code Live Server）開啟網站，不能直接以 `file://` 開啟。

目前購物車、商品與訂單資料僅儲存在瀏覽器 `localStorage`，付款僅提供門市付款展示流程；管理頁亦未加入登入與權限控管。正式營運前仍須串接後端、付款服務及管理者驗證。

## 5. 技術架構建議

- **前端（目前階段）**：原生 HTML、CSS 與 JavaScript ES modules；多頁間使用一般連結，共用 `styles.css`、`assets/js/app.js` 與 `data/products.json`。若後續互動複雜度增加，再評估 React 或 Vue 與路由套件。
- **後端**：Node.js／Express 或 Python／FastAPI，提供菜單、購物車結帳與訂單管理 API。
- **資料庫**：PostgreSQL 儲存商品、訂單、訂單明細與管理者資料。
- **即時狀態**：MVP 可先以定期查詢或 Server-Sent Events 更新訂單；需要雙向即時互動時再採用 WebSocket。
- **安全與可靠性**：由伺服器重新計價並驗證商品供應狀態；不可只信任前端送來的價格。付款結果、管理權限與訂單狀態需由伺服器控管。

## 6. MVP 範圍與驗收

### MVP 必要範圍

- 顧客端首頁、菜單、客製化、購物車、結帳與訂單追蹤。
- 管理端訂單看板與商品上／下架、缺貨設定。
- 手機與桌面基本 RWD。
- 至少一種可實際完成的付款或現場付款流程；未串接的第三方付款方式須明確標示未啟用。

### 驗收重點

- 顧客能從首頁進入菜單，完成選品、客製、結帳並取得可追蹤的訂單。
- 商品價格與訂單總額由伺服器驗證；缺貨品項無法送出訂單。
- 管理者更新訂單狀態後，顧客可看到正確進度。
- 主要頁面在手機與桌面均可操作，表單錯誤與系統錯誤皆有清楚提示。

## 7. 開發里程碑

| 階段 | 工作內容 | 產出 |
|---|---|---|
| Phase 1：需求與視覺確認 | 確認流程、頁面架構、品牌視覺與首頁試作 | Wireframe、UI 規範、首頁原型 |
| Phase 2：顧客端前端 | 建立獨立 HTML 頁面、共用 JS 模組、JSON 菜單資料、客製、購物車與結帳介面 | 可操作的多頁式顧客端介面 |
| Phase 3：API 與資料庫 | 建立商品、訂單及管理 API，加入伺服器端價格與狀態驗證 | API、資料庫 Schema |
| Phase 4：管理端與整合測試 | 訂單看板、菜單管理、狀態更新與完整流程測試 | MVP 測試版本 |
| Phase 5：部署與優化 | 部署、監控、效能與使用者體驗優化 | 可上線版本 |
